# Архитектура нового Telegram-клиента

20.10.2026. Цель Алексея: копия актуальной Android-игры с особенностями Telegram. Выбор Vue3/TypeScript/Vite — рабочее решение агента для начального каркаса; это не утверждение, что Vue объективно быстрее всех альтернатив.

## Почему этот стек

| Вариант | Оценка для этого проекта |
|---|---|
| Vue3 + отдельный Canvas | Рекомендуется: компонентные окна/состояния, близость существующего HTML/CSS-прототипа, движок можно переносить независимо от UI |
| Svelte | Также подходит. Потенциальные отличия размера сборки без сопоставимого прототипа не доказывают заметной пользы для нашей игры; замеров сравнения нет |
| React | Подходит технически, но готового React-клиента/библиотеки проекта нет; преимущества, ради которого менять направление, не выявлено |
| Vanilla JS | Минимум зависимостей; при большом числе окон, состояния кошелька и серверных операций придётся вручную поддерживать больше связей |
| Phaser/новый игровой движок | Другая категория инструмента. Может управлять сценой/физикой, но требует согласовать поведение с Android и серверным replay заново; для нынешней простой Canvas-аркады не обоснован |

Основание: [Vue](https://vuejs.org/guide/introduction.html), [производительность Vue](https://vuejs.org/guide/best-practices/performance.html), [Svelte](https://svelte.dev/docs/svelte/overview), [React](https://react.dev/learn), [Phaser](https://docs.phaser.io/phaser/getting-started/what-is-phaser), [Vite](https://vite.dev/guide/). Рекомендация основана на устройстве проекта, а не сравнительном измерении FPS.

## Границы модулей

При добавлении функционала соблюдать структуру:

```text
src/
  app/          Vue root, layout, lifecycle и стили
  components/   общие окна, HUD, EnergyRewardMotion, AverageChart
  features/     энергия, профиль, рейтинг, результат, возраст и помощь
  domain/       viewport/RMS/reward math и JS-мост к Dart
  game/         ввод/RAF, Canvas painter и косметический ImpactBurst
  platform/     Telegram SDK, звук, AdsGram и device-only audience
  services/     API, durable journal/store, Stars, reward delivery
  generated/    зафиксированный bundled Android snapshot
public/kernel/  скомпилированный Dart и hash-манифест
qa/             отдельные DEV fixtures; не production entry
```


- Vue управляет экраном, окнами, кошельком и редкими обновлениями HUD. Позиции врагов и игрока не помещать в глубокую реактивность на каждом кадре.
- Симуляция не импортирует Vue/DOM/Telegram. Canvas-отрисовка и управление подписками/кадровым циклом — отдельные адаптеры. Остановка при фоне/рекламе, dispose при закрытии.
- Эталон поведения — актуальные Android-исходники и серверный replay, а не старая Telegram-физика. На20.10: Android188/serverv21, формула `weighted_rms_v1`, последние50/вес92%/порог0/допуск1. Перед следующим этапом перечитать память: эталон может обновиться.
- Общий сервер определяет личность, платформу, баланс, награды, стоимость попытки и приём результата. UI не начисляет демонстрационные награды самостоятельно.
- Общие механика/настройки/выдача энергии; отдельные товары, покупные цены и сроки подписок. Провайдер входа не равен платформе.
- Telegram initData проверяется сервером. Stars-секреты и вебхук не входят в браузерный bundle. Платёжный обработчик не является Static Site.
- Новый localStorage namespace и новый профиль: не читать `untouch_tg_economy` старого клиента, не импортировать прежние балансы.
- `telegram-web` используется для чтения как история Telegram-интеграций. Никаких runtime-импортов, symlink, копирования его config-data, PHP-секретов или player data в новый клиент.
- UI-kit — источник оформления, не проверенный сервер и не окончательный источник формул/цифр. Общие изображения брать из существующих assets по явному списку, без упаковки всей папки проекта.

## Приёмка порта

Первый вертикальный этап: подписанный Telegram-вход → снимок RC → новый серверный кошелёк → запуск → проверенный результат → рейтинг. Повтор запросов не меняет баланс дважды; произвольный клиентский ID не выбирает чужой кошелёк.

До общего рейтинга: одинаковые seeded-фикстуры Android/JS/server, движения/столкновения/шлем/прыжок/старт, стоимость и завершение попытки; версия правил фиксируется на попытку. Общие коды приглашений проверяются по четырём направлениям платформ и условиям подтверждённого входа.

Физическая приёмка: настоящий Telegram Android и iOS, производительность, ввод/фон/звук, загрузка и сеть. Одна успешная сборка Vue не доказывает готовность игры.

## Доставка

По прямому указанию Алексея сначала выполняется перенос и проверка соответствия, только затем — отдельный этап Render. Сервис/домен/ветка автодеплоя Render не создавались. Временный HTTPS QA разрешён поQ3 и поднимается отдельным gateway с изолированной PGlite, настоящим HMAC и без fixture-session/платежей/рекламы. Он не является production. Общий tools/build_telegram_web.ps1 расширен явным -VueTelegram режимом; прежние режимы сохраняются. Новые QA-релизы версионные и неизменяемые. FTP/push/Render не выполняются.

## Реализованные границы и текущая проверка

GameWorld, MobileGameplayTuning и GameStartGuard компилируются из hash-проверенного Android188 snapshot в public/kernel/android-world.js. Vue получает неглубокий HUD-снимок; Canvas обновляется отдельно. ImpactBurst/face/near-miss — только отображение, не новый физический движок. Добавочные cosmetic fields не входят в proof.

Telegram identity — отдельная запись external_identities и случайный UUID в том же игровом хранилище. Она не выдумывает Google Auth пользователя. Новая совместимая миграция объединяет Android/TG record/RMS и directory platform filters. В runtime shared RC materializes Android-compatible snapshot; scoped drafts/ETag/audit защищают чужие платформенные настройки.

Local storage namespace untouch_tg_v2. Prepared intent сохраняется до списания; pending proof не выбрасывается. После подтверждения heavy proof/config удаляется из terminal history, остаётся до600 лёгких записей. Один writer через Web Locks. При storage failure до старта партия не начинается; после finish результат удерживается в памяти и блокирует потерю через навигацию. Нельзя обещать сохранность RAM при kill.

Stars и AdsGram проходят отдельную серверную доставку. openInvoice callback не начисляет энергию. SDK onReward — модель рекламного MVP, не криптографическое доказательство просмотра. salesEnabled=false/integrationAccepted=false и пустые ads IDs сохраняют внешние продажи/показы выключенными. Настоящие платёжные тесты явно отложены пользователем.

Приёмка и ограничения перечислены в матрице, общий P10 не принят. Не путать138 backend tests/93 independent tests с реальным устройством или опубликованным релизом.
