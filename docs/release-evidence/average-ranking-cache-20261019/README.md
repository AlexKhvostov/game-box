# Кэш среднего рейтинга — внедрён

Завершение: 20.10.2026, Europe/Minsk. Начато 19.10.2026. Android API **v20 ACTIVE**; новая версия приложения не требуется. Квадратичная формула остаётся только сравнением в UIKit.

## Где хранится

- Сервер: `untouch.average_rank_cache`, одна строка готового агрегата на профиль. Таблица приватная, RLS включён, прямого доступа у `anon`/`authenticated` нет. Профиль удаляется — агрегат удаляется каскадно. Имена, видимость и места не кэшируются этим слоем.
- Служебная версия истории: `untouch.average_score_revisions`. Триггер изменяет её в одной транзакции с добавлением/исправлением/удалением подтверждённой Android-попытки. Метаданные версии сохраняются после удаления профиля, чтобы предотвратить повторное использование старой версии при запоздавшем запросе.
- Телефон уже сохранял готовый ответ в SharedPreferences, ключ `average_ranking_v1_<owner>` с префиксом окружения. Эту клиентскую логику задача не меняла.

Повторное чтение использует готовый агрегат. После изменения попыток или правил пересчёт выполняется при следующем чтении, только для устаревших строк. Пустой результат тоже кэшируется. Ключ правил включает версию алгоритма, окно, порог, вес и минимум попыток. Игровое завершение не получает дополнительного расчёта среднего; добавляется только обновление номера версии истории. Исходная история сохранена, агрегат восстанавливаемый. Новой формулы и новых клиентских запросов нет.

## Проверки

- [Общий backend-прогон](backend-tests.txt): **116 PASS**. После добавления отдельного игрового сценария [целевые проверки](cache-tests.txt): **10 PASS**. Это 117 различных тестов в двух прогонах, 9 пересекаются.
- Холодный/повторный запросы совпадают с сохранённой старой реализацией; проверены окно/порог/давность/смена RC, короткие попытки, разные владельцы и платформы, исправление/удаление/порядок, имена/модерация/места, пустой/удалённый профиль, rollback, защита от записи более старой ревизии и серверные роли.
- Изолированный сценарий принятой попытки: start → activate → finish → allPeriods обновил кэш один раз; повтор finish сохранил баланс и не создал вторую попытку. Реальные раунды/QA-аккаунты для проверки не создавались.
- [Локальная проверка плана](local-verification.json), [действующая база до публикации](live-verification.json), [после публикации](live-after-deploy.json): **29 профилей / 29 строк кэша**, 12 участников рейтинга; JSON-ответ совпал с прежней формулой. Контрольная сумма всех 1164 документов до/после совпала в одном согласованном снимке. Повторный запрос не обновляет строки кэша; `EXPLAIN ANALYZE` показывает **0 выполнений чтения scores**. Время сетевого обращения не выдаётся за время SQL: warmMs включает сеть, planExecutionMs относится к выполнению в БД.
- Авторизация API после внедрения: запрос без токена → **401 unauthorized**. Режим проверки JWT шлюзом оставлен прежним; собственная проверка токена в handler сохранена. Аутентифицированный HTTP-запрос с реального телефона в этой задаче не выполнялся; проверены движок локально и тот же SQL под рабочей серверной ролью в действующей БД.
- Проверка Supabase Advisors: замечаний безопасности к новым объектам нет. Единственная новая информационная отметка — пока не использованный индекс `average_rank_cache_owner`, предназначенный для каскадного удаления профиля. Удалений реальных профилей не было, индекс сохранён. [Описание отметки](https://supabase.com/docs/guides/database/database-linter?lint=0005_unused_index).
