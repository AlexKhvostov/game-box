## Что исправлено

Убрана введённая при ревью безусловная блокировка `rewardVerificationAvailable=false` и запрет всех `watch_ad` на сервере. Восстановлен штатный путь Yandex, без смены сети и экономических настроек. Возраст18+, отзыв разрешения и запрет автоматической рекламы после одного rewarded-нажатия сохранены.

Перед загрузкой рекламы приложение подтверждает на сервере одноразовую сессию. Она привязана к игроку; размер награды фиксирует сервер из действующей конфигурации. Только результат SDK `rewarded` приводит к команде начисления. Сервер проверяет сессию, срок24ч, повторное использование и cooldown; операция и кредит записываются одной транзакцией. Повтор того же operationId возвращает подтверждение без новой награды. Прямой старый `watch_ad` без сессии отклоняется. Если первый ответ сервера потерян, журнал сохраняет точную команду и повторяет её; новый просмотр не нужен. До подтверждения UI не обещает кредит.

Раннее закрытие/отсутствие рекламы не начисляет энергию. Смена владельца, закрытие маршрута или отзыв до показа отменяют показ. Смена владельца после показа не переносит награду другому игроку. Ранее добавленная защита native-окна от потери callback сохранена.

## Фактическая граница защиты

В этой внутренней сборке показываются **официальные демонстрационные объявления Yandex**, как до ревью; это настоящий SDK/показ, но не live-монетизация. Награда в основном приложении — настоящая серверная энергия. Live ad unit IDs и публикация в магазине этой задачей не включались.

[Yandex прямо сообщает](https://ads.yandex.com/helpcenter/en/support/faq/sdk-integration), что server-side rewards не поддерживаются. [Штатная интеграция](https://ads.yandex.com/helpcenter/ru/dev/flutter/rewarded) использует callback `onRewarded`. Реализованные сессии ограничивают повтор/владельца/награду/откат, **не являются криптографическим доказательством просмотра**. Изменённый клиент по-прежнему может имитировать SDK-исход. Поэтому замечание F03 нельзя считать полностью устранённым с точки зрения подделки просмотра; функция работает на штатном Yandex-механизме, остаточный риск явно сохранён. Предыдущее решение «выключить вместо восстановления» отменено прямым поручением Алексея.

Навыки: session-memory — план/передача; Supabase — безопасная доставка, runtime/SQL/данные.
