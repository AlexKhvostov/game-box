## Админка

Вход через Google сам по себе не выдаёт права. Сервер проверяет enabled в приватной admin_users на каждом запросе. Единственный разрешённый владелец назначен по явно подтверждённой Google identity; пользовательские metadata прав не дают.

- «Параметры Remote Config»: разделы, поиск, диапазоны, часы бонуса, черновик, предпросмотр и отдельная публикация. Служебные поля и параметры снятых механик (батарей, достижений, прежнего HUD/вибрации) скрыты и сохраняются для совместимости. Полный аудит120 полей:57 редактируемых,63 скрытых — docs/ANDROID_PARAMETER_AUDIT_20261016.md. Внутренняя обратная связь возвращена:50 энергии один раз после100 суммарно потраченной энергии. Учитываются только активированные попытки, отменённые старты исключены. Оценка необязательна и не влияет на награду; сообщение не публикуется в Google Play.
- «Пользователи»: все Auth-аккаунты, включая ещё не запустивших игру; поиск по ID, нику и точной почте. Есть состояние, баланс, подписка, активность, карточка, внутренние отзывы и журнал поддержки. Баланс задаётся абсолютным числом с обязательной причиной; повторы защищены requestId, устаревшее состояние — expectedVersion.
- Удаление требует точного ID и подтверждения предупреждения Google Play. Во время удаления профиль блокируется. Удаляются Auth и игровые персональные данные; подтверждённые анонимные хеши покупок и минимальный журнал поддержки остаются. Подписка/возврат денег в Google Play автоматически не меняются. Себя и других администраторов через эту форму удалить нельзя.
- «Отзывы»: общий список внутренних сообщений с автором/ID/почтой Google при наличии, датой, полным текстом и оценкой либо «Без оценки». Поиск по тексту/нику/ID, фильтр оценки,25 на страницу; переход в карточку игрока. Доступ только текущему администратору; текст экранируется. Настоящих отзывов пока0; заполненное отображение проверено локально, тестовые сообщения в базу не добавлялись.
- «История публикаций»: только изменения через эту админку. Первоначальный bootstrap RC46 выполнен отдельно; RC47 — проверка публикации без изменения значений, записанная в журнал.

Remote Config публикуется с точным ETag, без wildcard-перезаписи. Меняется только android_config_v1; другие параметры, группы и условия сохраняются. Сервер использует подтверждённую публикацию для немедленного сброса своего кеша; прямые изменения в Firebase Console обнаруживаются в пределах5мин. Клиент загружает настройки при полном запуске, минимум1мин между загрузками (сборка154 и далее); при rules_changed просит перезапуск и принудительное обновление. Уже начатая попытка хранит собственную версию правил.

Firebase Analytics в Android отключена. Сохранение Remote Config оставляет основу для будущих A/B, но сами эксперименты ещё не готовы: потребуется отдельно включить/согласовать Analytics и серверное назначение экономических вариантов. Текущая админка откажет в публикации единого JSON, если у Android-параметра уже есть условные варианты, чтобы их не затереть.

## Сервер и защита

Edge Functions android-api, remote-config-admin и support-admin самостоятельно проверяют JWT через Supabase Auth getUser. Поэтому внешний JWT gateway отключён осознанно, а не вместо проверки доступа. play-reconcile принимает только отдельный серверный ключ с безопасным сравнением. Публичный publishable key не даёт доступа к приватным таблицам.

Игровые записи — в закрытой схеме untouch с RLS; браузер и игра не могут напрямую менять документы или выдавать себе admin. SQL-роль untouch_runtime ограничена игровыми таблицами и узкими функциями каталога. Она не читает auth.users напрямую, не меняет admin_users, подключается через transaction pooler с проверкой TLS/официальным CA. Транзакции SERIALIZABLE, обработка повторов и фиксированные SKU проверены локально и на реальном PostgreSQL.

Google unlink готовится стандартным Auth Admin update для той же почты, уже подтверждённой Google. Не принимаются email/UID из тела запроса и не создаётся скрытый пароль. После появления второй email identity клиент удаляет Google identity обычным SDK и проверяет сохранение UID. Настоящий Google-вход на Huawei прошёл под аккаунтом владельца; проверка отвязки личного аккаунта остаётся отдельной от тестов Auth Admin на временном профиле.

Без Google Cloud Billing использован Supabase Cron: каждую минуту вызывается play-reconcile. Ключ хранится в Vault. Работник берёт ограниченную партию известных покупок, блокирует параллельный запуск, повторяет подтверждения, сверяет подписки и возвращённые заказы. Возврат сопоставляется одновременно по известному токену и номеру заказа: старый возврат продления не отменяет более новое продление того же токена. При большом числе покупок полный обход занимает несколько запусков. Настоящие списания не выполнялись. Настоящий license-testing Play прошёл успешный100,отклонённый250,pending→успешный500 с восстановлением,жизненный цикл×2/×5 и возврат тест100; все Google API отмечены TEST. Финально подписки EXPIRED, активные права сняты, баланс869. Подробности/границы — в текущем отчёте.

Остаются замечания Supabase advisors: политики managed-таблиц cron относятся к PUBLIC, хотя схема недоступна игровым ролям, а строки ограничены username=current_user; владельца расширения изменять нельзя. Проверка скомпрометированных паролей выключена. В игре нет входа по введённому паролю, ключи/пароли не публикуются. Это не основание объявлять все advisors пустыми.

## Мгновенная игра и временное отсутствие сети

С17.10.2026 текущая Supabase-сборка начинает движение и таймер синхронно от касания. Надпись «Подготавливаем попытку» удалена. Remote Config загружается при старте приложения, а клиентская сеть не входит в обработку полевого касания.

InstantRoundJournal хранит на устройстве отдельные requestId/owner/выбор шлема и прыжка/версию правил/расход/результат каждой попытки. Весь расход вычитается из доступного локального остатка, пока сервер не подтвердит соответствующее списание; кеш проверяется по secure owner. Новых денег локальная очередь не создаёт. HTTP начинается после сохранения намерения на диск. Завершённая история сохраняется до результата сети и восстанавливает метрики, если процесс остановился между двумя записями.

При восстановлении связи сервер последовательно проверяет и подтверждает все попытки. Общий рейтинг по-прежнему показывает лучший результат игрока, но счётчики/расходы/награды требуют всех записей. Используются прежние round_start/activate/finish, их nonce/серверные цены/бусты/elapsed-time не ослаблялись. Поздний activate откладывает только отправку результата, не игру; подготовка других ожидающих записей продолжается. Повторы и потерянные ответы не списывают энергию повторно.

Синхронизация работает при открытой игре/возврате в неё; Android force-stop не запускает фоновые задания сам. Самый первый профиль требует сети; затем известный owner/кошелёк/очередь восстанавливаются офлайн. Подтверждение наград и публичного результата остаётся серверным. При постоянном отказе (недостаточный серверный баланс, изменившиеся правила, блокировка профиля) запись остаётся в локальной истории без опубликованного результата; произвольные старые политики не принимаются. Очередь ограничена10000 незавершённых синхронизаций.

Активная игра блокирует смену identity. Завершённая очередь допускает восстановление Google-входа: записи остаются в локальном разделе исходного owner. Транспорт проверяет expectedOwner против текущей Supabase session и не создаёт нового гостя ради повторения чужой очереди.

[Отчёт и физические проверки](release-evidence/instant-round-20261017/FINAL.md).

## Секреты и доставка

Исходники — в проекте. Служебные ключи и OAuth JSON — вне проекта в LocalAppData/Untouch/private; DPAPI-резервы доступны только текущему Windows-пользователю. Ключи сервера загружены в Supabase Secrets. В админку/APK входят только публичные URL/key и Google client ID. Официальный Supabase CLI получает секретные SQL/env через временные Windows named pipes, без аргументов с паролем и plaintext-файлов проекта.

Админку собирать npm --prefix admin-console run build; публиковать из admin-console только explicit hosting site в его firebase.json. Android Hosting имеет отдельный supabase/firebase.json. Default Firebase Hosting, старую MySQL/Firestore и Telegram не заменять. Git push и Google Play release не выполнялись.

Проверки и артефакты: [отчёт](release-evidence/supabase-admin-20261016/FINAL.md). Старые покупки с SQL/Firebase owner не присваиваются произвольному Supabase UID; автоматического переноса прежних балансов/результатов нет.

Официальные описания: [Identity linking](https://supabase.com/docs/guides/auth/auth-identity-linking), [Auth Admin implementation](https://github.com/supabase/auth/blob/master/internal/api/admin.go), [планировщик Edge Functions](https://supabase.com/docs/guides/functions/schedule-functions), [Voided Purchases API](https://developers.google.com/android-publisher/api-ref/rest/v3/purchases.voidedpurchases/list).
