# Три независимых формата рекламы

27.10.2026. Рабочие админка/RC78/APIAndroid38/Telegram22/Admin27 обновлены. Android229 с альтернативным порогом игр установлен на основной телефон без сброса данных. [Три формата](../memory/tasks/2026-10-27-ad-formats-controls.md), [время или игры](../memory/tasks/2026-10-27-banner-unlock-criteria.md).

## Управление

В общих настройках админки три отдельных раздела. Баннер пока относится к Android; существующие общие интервалы автоматической рекламы Android/Telegram сохранены.

| Раздел | Настройки |
|---|---|
| Баннер | Включение, секунды от установки ИЛИ завершённые игры, отдельный баннерный ID Яндекса |
| Автоматическая реклама | Включение, задержка от установки, пауза после открытия, первые партии без рекламы, интервал между роликами, порог энергии, порог долгого отсутствия, пауза после возврата |
| Реклама по запросу | Включение, награда, откат, лимит успешных наград за сутки |

Выключатель одного формата не меняет другие. Ограничения возраста/согласия продолжают действовать. На время полноэкранного показа баннер временно убирается без изменения его выключателя.

## Параметры

Новый необязательный объект конфигурации: `advertising`.

| Поле | Значение при отсутствии в старом RC |
|---|---|
| `advertising.banner.enabled` | `false` |
| `advertising.banner.installDelaySec` | `86400` (сутки; рабочее начальное значение агента) |
| `advertising.banner.unlockAfterGames` | `100` завершённых игр; `0` отключает критерий количества |
| `advertising.banner.unitId` | пустая строка |
| `advertising.automatic.enabled` | `true`; дополнительный переключатель Telegram сохраняется |
| `advertising.automatic.longAbsenceSec` | `300` (5 минут) |
| `advertising.automatic.resumeGraceSec` | `180` (3 минуты) |
| `advertising.rewarded.enabled` | `true` |

Задержки — целые секунды0–2592000, количество игр — целое0–1000000. Баннер разрешается при первом выполненном условии: время после установки ИЛИ завершённые игры. Нулевое время разрешает сразу, нулевое количество оставляет только время. Счётчик накапливается на установке даже при OFF и сохраняется между запусками/сменами аккаунта; начатая или прерванная без результата игра не считается. У старых установок достоверной истории этого локального счётчика нет: он начинается с обновления, OSдата установки сохраняется. OFF/возраст/согласие/подписка остаются обязательными ограничениями.

ID баннера — пустой либо `R-M-число-число`. Рабочий блок `R-M-20184253-3` создан; площадка пока в тестовом статусе. Неверные типы/значения отвергает сервер. Коммерческий баннер без ID не запрашивается; DEMO использует отдельный официальный ID.

Прежние `economy.interstitialGraceSec`, `interstitialSessionGraceSec`, `interstitialSessionFreeRounds`, `interstitialCooldownSec`, `interstitialMinLives` сохранены на прежних местах JSON и сгруппированы только в разделе автоматической рекламы. Рабочий RC78:500/500/10/400/10; старый bundledasset210/180/10/220/6 — исторический fallback. Награда40, откат120с и лимит20 за сутки остаются настройками рекламы по запросу.

Новые поля живут в `untouch_platforms_v1.common.advertising`; штатная публикация формирует совместимый `android_config_v1`. Чтение старого RC не добавляет поля, не меняет ревизию и не публикует значения. Предпросмотр сравнивает отсутствующие поля с их реальными значениями по умолчанию: две правки баннера дают две строки, а не ложные изменения всех форматов.

Ранние отдельные ключи `android_bottom_banner_enabled`/`android_bottom_banner_unit_id` заменены этой схемой; создавать их не следует. В рабочий RC они ранее не публиковались.

## Установка и возврат

Android читает `PackageInfo.firstInstallTime` собственного пакета один раз при запуске. Дата сохраняется локально, не сбрасывается при обновлении и не зависит от аккаунта. Для старой нативной части без этого поля остаётся сохранённая дата первого открытия.

Таймер баннера запрещает рекламный запрос до окончания задержки. Выключение/отсутствие допуска скрывают полосу; ошибка не создаёт непрерывного цикла запросов.

Для автоматической рекламы одновременно должны пройти все ограничения. При любом сворачивании ожидающий показ теряет право запускаться; возврат не восстанавливает старую загрузку. После любого возврата начинается `resumeGraceSec`. После отсутствия не меньше `longAbsenceSec` пауза составляет не меньше `interstitialSessionGraceSec`. Например, возвратная пауза10с, порог300с и пауза открытия180с дают10с после короткого сворачивания и180с после долгого отсутствия.

Истечение таймера само по себе не запускает ролик: показ по-прежнему относится к переходу после результата. Уже открытый экран SDK не подменяется собственной кнопкой закрытия. Алексей уточнил27.10: до сворачивания был экран игры/результата, ролик ещё не открывался; именно ожидающий показ защищён новой логикой.

Баннер перечитывает RC при запуске, возврате и раз в минуту на переднем плане. Остальные правила применяются при запуске и штатной синхронизации перед новой партией. Это не мгновенный push; без сети остаются сохранённые правила. Условия начатой оплаченной партии не меняются.

## Реклама по запросу

Выключение запрещает новые запросы в Android/Telegram; сервер также отказывает в создании новой рекламной сессии. Уже выданная сессия сохраняет право подтвердить заработанную награду. Лимит/откат по-прежнему проверяются сервером.

## Проверка и выпуск

QA223 исправила ошибочные интервалы баннерной примерки. QA224 содержит новые модели/защиту возврата и установлена отдельным пакетом `.uiprobe.banner`; основная219 прежняя. В QA — искусственный профиль/кошелёк и настоящий Yandex DEMO. Для визуальной примерки источник баннера принудительно включён без задержки; это не проверка управления телефоном из рабочей админки. Реальная основная точка запуска читает общий RC.

Локальная собранная админка: `http://127.0.0.1:5191/?preview=1`; изменения не отправляются в Firebase. [Снимки и доказательства](release-evidence/ad-formats-20261027/README.md).

Для общего выпуска нужны согласованные обновления серверной проверки, админки и основной Android-версии. Старые Android219/221 не знают новых выключателей и таймера возврата; новая форма не обновит старые приложения. Коммерческий баннер/модерация — отдельный этап. Плотность партий сверх прежних ограничений не добавлялась: Алексей отложил обсуждение.

## QA с Firebase RC · новое поручение 27.10

QA225 установлена поверх QA224 в отдельный `.uiprobe.banner`, без очистки данных. Принудительный баннер и локальный `/banner-config` удалены из новой точки запуска. Четыре сочетания ON/OFF проверены на Huawei, включая настоящий DEMO-баннер и один полноэкранный SDK-показ после обычных ограничений. Итог — оба OFF, QA остановлена. [Физические доказательства](release-evidence/ad-formats-rc-qa225-20261027/README.md), [отчёт](../memory/tasks/2026-10-27-ad-formats-controls.md).

QA читает отдельный параметр Firebase `android_ad_formats_qa_v1`: JSON того же объекта форматов (`banner`, `automatic`, `rewarded`). Основная игра и Telegram этот ключ не используют. Отсутствие или неполный JSON не разрешают рекламу: начальное состояние обоих форматов OFF. Успешное чтение обновляет баннер и автоматическую рекламу одним снимком. Ошибка сети сохраняет ранее полученные правила, как в основной версии.

В начальном тестовом RC оба формата OFF, задержка баннера 0 секунд для проверки. Это значение находится в RC, а не принудительно в клиенте. Прочие интервалы автоматической рекламы остаются 210/180/10/220; для просмотра требуется пройти обычные ограничения. DEMO выбирает только тестовый рекламный блок Яндекса, не включает формат.

Локальный инструмент `node tools/qa_ad_formats_remote_config.mjs` без параметра публикации показывает подготовленный QA JSON. `--banner=on|off`, `--automatic=on|off` меняют только отдельный тестовый параметр; `--publish` выполняет запись с ETag, зашифрованной резервной копией и проверкой неизменности остальных параметров. Это не публикация основной админки или правил игроков. Для повторного чтения уже опубликованного RC в QA есть `/rc-refresh`: он не принимает локальных значений выключателей.
