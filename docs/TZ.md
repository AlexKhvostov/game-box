# Game Box — техническое задание (ТЗ)

## 1. Стек и архитектура

| Слой | Выбор | Зачем |
|------|--------|--------|
| Клиент | **Flutter** (Dart), Android первым | Один код → iOS без переписывания UI |
| Backend | **Firebase** (не MySQL на старте) | Auth + данные + конфиг без своего API-сервера; MySQL имел бы смысл позже при своём бэкенде |
| Auth | Anonymous Firebase Auth | Игрок есть сразу, без регистрации |
| Данные | Cloud Firestore | Профиль, результаты, рейтинг |
| Конфиг | **Remote Config** (+ при желании doc в Firestore) | Параметры экономики/сложности меняются без нового билда; удобно A/B и тесты |
| Покупки | Google Play Billing (in_app_purchase) | Пакеты жетонов; в MVP — по возможности |
| Локально | shared_preferences / hive | Кэш жизней, таймеров daily/8ч при офлайне |

### Структура клиента (логически)

```
lib/
  main.dart
  app/           # тема, роутинг, shell с нижним меню
  features/
    game/        # поле, физика/коллизии, цикл партии
    result/      # экран результата, сохранение ника
    leaderboard/ # таблица
    profile/     # жизни, жетоны, daily, 8ч, магазин
    economy/     # правила списания/начисления
  data/          # репозитории Firebase + локальный кэш
  domain/        # модели: Player, Score, EconomyConfig
```

Образец на Kotlin ([NikitaChaichits/game-box](https://github.com/NikitaChaichits/game-box)) — только референс механики «квадрат vs враги», в прод не переносится.

## 3. Экраны и поведение

### 3.1 Shell

Нижняя навигация: **Игра** | **Рейтинг** | **Профиль**.

### 3.2 Игра

1. Показ жизней и жетонов (кратко в шапке).
2. Кнопка «Играть».
3. Если lives <= 0 → экран/модалка заморозки (купить пак / получить жетоны / в магазин).
4. При старте: lives -= 1 (серверная транзакция или безопасный update), затем игровой цикл.
5. Поле: игрок drag; враги спавнятся и едут; AABB-коллизия; таймер ms.
6. Конец → экран результата (жизнь уже списана).

### 3.3 Результат

- Время (сек с десятыми).
- Запрос ранга и процентиля (см. §4).
- Кнопки: Сохранить / Не сохранять / Ещё раз (если есть жизни).
- Сохранить: поле имени (если пусто — ввод; если есть — подтверждение тем же или смена).

### 3.4 Рейтинг

- Топ-N по timeMs desc (fair == true).
- Подсветка текущего игрока, если есть в топе / показ своего места.

### 3.5 Профиль

- Ник, лучшее время, жизни, жетоны.
- Daily Reward: активна / «завтра» + streak.
- Кнопка жетонов: активна / таймер до nextTokenBonusAt.
- Вход в магазин IAP.
- Настройки (звук вкл/выкл — минимум).

### 3.6 Магазин

- Список пакетов жетонов (IAP).
- Если Billing ещё не подключён: заглушка «Скоро» или тестовые продукты; экономика free-источников уже работает.

## 4. Рейтинг: место и процентиль

1. Клиент после партии (и при сохранении) запрашивает агрегат:
   - `betterCount` = число сохранённых результатов с timeMs > текущего (или >= — зафиксировать: **строго лучше** для «быстрее»).
   - `totalCount` = число сохранённых результатов.
2. Место ≈ `betterCount + 1` (для личного результата; уточнение: место по лучшему времени игрока vs по этой партии — **в MVP место считается для только что сыгранной партии среди всех сохранённых результатов**).
3. Процентиль: `round(100 * (1 - betterCount / max(totalCount, 1)))` → «быстрее X%».
4. Оптимизация позже: Cloud Function / счётчики; на старте допустимы запросы Firestore с индексами и лимитами.

**Сохранение:** создаёт/обновляет Score; обновляет `bestTimeMs` игрока, если новый рекорд; назначает `displayName` / `nameTag` при необходимости.

**Коллизия имён:** если displayName занят другим uid — генерировать nameTag (4 цифры) и показывать `name#tag`.

## 5. Экономика: правила

| Действие | Условие | Эффект |
|----------|---------|--------|
| Старт партии | lives > 0 | lives -= 1 |
| Daily claim | календарный день новый относительно lastDailyClaimAt | tokens += daily[streak]; streak++ или reset |
| Timed bonus | now >= nextTokenBonusAt | tokens += timedBonus; next = now + 8h |
| Купить жизни | tokens >= cost | tokens -= cost; lives += packSize |
| IAP | успешная покупка | tokens += pack.tokens |

Все начисления/списания — через репозиторий с проверкой на клиенте + правила Firestore (по возможности Functions для IAP-валидации).

## 6. Игровой цикл (детали MVP)

- Размер игрока и врагов — константы в коде (как в образце: ~40 / ~60 px logical).
- Спавн: с края поля, случайное направление внутрь/через поле.
- Скорость и интервал спавна растут от `elapsedMs` (формулы в коде, тюнинг).
- Кадр: `Ticker` / `GameLoop`; отрисовка `CustomPainter` или Flame (опционально; MVP достаточно CustomPainter).

Рекомендация MVP: **CustomPainter + GestureDetector**, без Flame — меньше зависимостей.

## 7. Критерии приёмки MVP

- [ ] Android-сборка запускается.
- [ ] Три вкладки: Игра, Рейтинг, Профиль.
- [ ] Партия: управление, враги, столкновение, таймер.
- [ ] При 0 жизней старт блокируется; пак жизней за жетоны работает.
- [ ] Daily и кнопка 8ч начисляют жетоны по правилам.
- [ ] Результат показывает время; при онлайн — место и % (или честный fallback «нет сети»).
- [ ] Сохранение с ником попадает в рейтинг.
- [ ] Remote Config (или локальный дефолт-конфиг) задаёт числа экономики.
- [ ] IAP: либо рабочие тестовые продукты, либо явная заглушка в ТЗ-чеклисте как «отложено на +1».

## 8. Безопасность (минимум)

- Firestore rules: писать scores только от своего uid; нельзя произвольно ставить огромный timeMs без ограничений (макс. разумный потолок, напр. 1 час).
- IAP: серверная проверка purchase token (фаза после базового Billing).
