# Прыжок готов: три варианта сигнала

Предложение24.10.2026. [Интерактивный эскиз](http://127.0.0.1:8919/docs/design/jump-ready-20261024/). Это отдельная страница для сравнения; она не импортируется Android, Telegram или живым UI Kit. Сначала пользователь выбирает оформление, затем отдельным этапом готовится игровой компонент. Публикация отложена до общего релиза по прямому указанию Алексея.

| Вариант | При переходе на100% | После сигнала | Комментарий |
|---|---|---|---|
| A · Золото + вспышка | Один тёплый белый импульс0,42с | Более светлое/яркое золото | Спокойное продолжение текущего оформления |
| B · Лимонная готовность | Один тёплый белый импульс0,42с | Светло-лимонные полосы | Рекомендация агента: устойчивое отличие видно, даже если вспышку пропустили |
| C · Блик вверх | Один светлый проход по полосам за0,42с | Жёлтый свет +2коротких верхних штриха | Дополнительное обозначение завершения через движение/форму |

Во всех вариантах лицо не подсвечивается вспышкой, размеры героя и шлема не меняются. Внешний контур шлема остаётся голубым. Игровой образец нарисован в44CSSpx; рядом увеличен в2,6раза. На узких экранах малый образец сохраняет44px. До100% используется существующая текстура полосок, с заполнением снизу вверх. Постоянного мигания нет.

Основа: `telegram-app/src/game/jump-glow.ts`, `lib/features/game/jump_glow.dart` и их вызовы в GameFieldPainter. Текстура построена по действующей формуле RGBA, радиус0,1. `current-jump-glow.js` — транспиляция только для эскиза, без правки источника; происхождение иSHAв`source-manifest.json`. Герой/лицо — Canvas по текущим игровым пропорциям, не архивный скриншот. ЖивойUIKit#abilities просмотрен: содержитHUDи демонстрацию2с, сами полосы принадлежат Canvasигры.

Управление: «Прыгнуть» показывает полный цикл2с; «Последние0,5с» — окончание зарядки; «Повторить только сигнал» — один импульс; шкала закрепляет процент, флажки дают сравнение со шлемом и без вспышки. В блоке «До/сигнал/после» показаны90%, пик импульса и стабильная готовность через1с.

Для будущего рабочего компонента: сигнал запускать от перехода фактической доступности прыжка false→true, с учётом и остатка перезарядки, и окончания полёта. На99,99% не обещать100%. Не запускать лишнюю вспышку при открытии готового экрана, не повторять её при каждом кадре/долгом ожидании. После использования сбросить; фон/пауза не продвигают игровую зарядку. При уменьшении движения оставить стабильное готовое состояние, убрать вспышку и движущийся блик. Это контракт предложения, не утверждение о переносе в игру.

Проверка страницы: `node docs/design/jump-ready-20261024/check-preview.mjs`. Результат и кадры — в `qa/`. Реальный телефон и игровая сборка этим этапом не проверяются.
