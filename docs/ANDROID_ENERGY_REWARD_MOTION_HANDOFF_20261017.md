## Что перенести

Один общий Flutter-компонент для двух событий, параметр суммы. Объёмная золотая молния с локальной вспышкой, одна расходящаяся волна, мягкие лучи и28 золотых/голубых искр со звёздами. Под символом крупная +N и подпись «энергии». Вместе с6 частицами награда уменьшается и перемещается к реальному балансу окна энергии; число плавно принимает сумму, коротко подсвечивается. Прямоугольной плашки, медали-монеты, золотой ленты, второго видимого toast, дополнительной кнопки подтверждения нет.

Во время раскрытия прежняя бонусная кнопка/её надписи скрываются, заголовок бонуса и плитка подписки приглушаются до18%, затем всё восстанавливается. Не менять геометрию окна. Полного затемнения окна нет. В UI kit для этого используются `receipt-source`, `receipt-on`, `receipt-target`; воспроизвести смысл в Flutter с корректным снятием состояния.

| Этап | Обычная скорость |
|---|---|
| Появление/раскрытие | 0–180мс |
| Чтение суммы/звёздный всплеск | 180–640мс |
| Перелёт награды к балансу | 640–1280мс |
| Рост числа и блик | 1200–1520мс |
| Удаление визуального слоя |1600мс |

Кривые движения/параметры брать из JS, не восстанавливать по одному PNG. Сниженная анимация —180мс, без перемещения/искр/вспышки/масштабирования. Свет локален. Повтор/выбор плана/замедление и ссылки из правой колонки UI kit в игру не переносить. Звук/вибрацию не добавлять в этой задаче.

## Интеграция без изменения экономики

1. В обоих случаях использовать одну реализацию анимации с фактической суммой операции и подтверждёнными before/after. Суммы30/60/150/40 в UI kit — демонстрационные значения текущей экономики, не повод захардкодить их в эффекте.
2. Бонус: только после подтверждённого нового получения сервером. Ошибка, очередь, ожидание, повторный sync или просто открытие окна не являются основанием играть успешный эффект. Сохранить текущую надёжную обработку операций/владельца и защёлку повторов.
3. Реклама: только награда настоящего rewarded SDK с существующим подтверждением экономики. Открытие/закрытие рекламы, ошибка, отмена/пропуск не дают ни ресурса, ни салюта. После закрытия SDK вернуться к видимому окну энергии и показать тот же эффект; уже закрытое пользователем окно/другого владельца не открывать принудительно.
4. Начисление и сохранение выполняются до визуализации; завершение/отмена анимации не управляют выдачей ресурса. Одна операция → одна выдача → максимум один показ.
5. Бонус8ч и рекламный cooldown2мин сохранить независимыми, от реального момента операции. Анимация не перезапускает и не продлевает их. Если настройки приходят удалённо — сохранить их источник.
6. Одна награда не должна накладываться на другую. Повторные события/клики не должны воспроизводить дубли; при уходе/смене владельца/dispose удалить временные эффекты и приглушение, сохранить подтверждённый баланс.
7. Фокус/доступность: один итоговый Semantics announcement, промежуточные значения не озвучивать. Без видимого повторного уведомления «получено» после завершения.
