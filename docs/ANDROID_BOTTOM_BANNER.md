# Нижний баннер Android · D-034

Пробная реализация27.10.2026, ветка `codex/android-bottom-banner`. Telegram не переносился. Объявление Яндекса размещается под зоной управления внутри SafeArea, без наложения на поле и системную навигацию. Используется `BannerAdSize.inline(width: ..., maxHeight: 50)`: высота ограничена API SDK, реклама не обрезается. Автоматический sticky на Huawei получился выше желаемого; для тонкой полосы выбран адаптивный inline, закреплённый снизу. Отступ от зоны управления8dp появляется только после загрузки. Общая система GameViewport масштабирует баннер вместе с интерфейсом.

## Удалённое управление

Актуальная схема: отдельный объект баннера в общем JSON Remote Config. [Три формата и совместимость](AD_FORMATS_CONTROL.md). Ранние скалярные ключи заменены до публикации.

| Параметр | Тип | Значение по умолчанию |
|---|---|---|
| `advertising.banner.enabled` | Boolean | `false` |
| `advertising.banner.installDelaySec` | Number | `86400` секунд |
| `advertising.banner.unlockAfterGames` | Number | `100` завершённых игр; `0` — только время |
| `advertising.banner.unitId` | String | пустая строка |

После обновления229 баннер разрешается по первому условию:86400с от установки ИЛИ100завершённых игр на этой установке. Оба порога управляются из рабочей админки; прогресс сохраняется между запусками. OFF всегда блокирует запрос независимо от достигнутых порогов.

Live-сборка запрашивает рекламу только с отдельным баннерным ID вида `R-M-…-…`, включённым флагом, возрастом18+ и сохранённым согласием на рекламные данные. Существующие ID rewarded/interstitial не подходят. БлокR-M-20184253-3 создан, рабочийRC78 и новая админка опубликованы; баннер покаOFF.

Проверка RC при запуске, возврате из фона и раз в минуту при открытом приложении; это не мгновенная команда. Действующий минимальный интервал Firebase также применяется. Если сети нет, сохраняется последнее полученное значение; первый запуск без значений — выключено. Уже установленные старые приложения новой функцией не обладают: сначала потребуется выпуск новой версии.

При выключении, отзыве согласия, открытии другого маршрута, полноэкранной рекламы или сворачивании нативный баннер освобождается. После ошибки загрузки место скрывается, повтор не чаще раза в минуту. До загрузки SDK использует свою техническую высоту1dp для создания нативного вида, видимой пустой рекламной полосы нет.

## Изолированная примерка

`powershell -File tools/build_android_automatic_ads_probe.ps1 -BottomBanner -BuildNumber 224`

Отдельный пакет `com.best4u.untouch.uiprobe.banner`, название `QA224 Untouch Banner` при исходной версии221. `YANDEX_DEMO_ADS=true`, `ANDROID_BANNER_PROBE=true`; настоящий SDK с официальным `demo-banner-yandex`. Возраст/согласие — искусственная QA-фикстура только отдельного пакета. Игровые запросы через MockClient: тестовый кошелёк/профиль, без Google, настоящих покупок и ресурсов основной игры. В интерфейсе можно играть для оценки баннера.

Loopback QA API8898 (только эта сборка): `/state`, `/banner-config?enabled=true|false`, `/banner-consent?enabled=true|false`. `/banner-config` проверяет клиентский путь применения настройки через подставной источник; это не реальное изменение Firebase RC.
