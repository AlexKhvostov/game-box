# Нижний баннер Android

Баннер Яндекса закреплён под игровой зоной внутри SafeArea. Размер задаёт SDK: `BannerAdSize.inline(width: ..., maxHeight: 50)`. Полоса не перекрывает поле;8dpотступ появляется только после загрузки, технический SDK-вид при загрузке имеет высоту1dp.

Параметры `advertising.banner`: `enabled=false`, `installDelaySec=86400`, `unitId=''` при отсутствии в старом RC. Коммерческий запрос возможен только с отдельным баннерным ID `R-M-…-…`, включённым форматом, подходящим возрастом18+и сохранённым согласием. DEMO меняет рекламный ID, но не включает формат. [Все3формата и интервалы](AD_FORMATS_CONTROL.md).

Источник проверяется при запуске, возврате и раз в минуту в переднем плане с учётом Firebase fetch interval. При отсутствии сети остаётся последнее полученное значение. OFF снимает нативный вид и освобождает место; открытая полноэкранная реклама/другой маршрут/сворачивание временно убирают баннер. Повтор после ошибки не чаще раза в минуту.

QA225 проверена на Huawei: реальный Firebase `android_ad_formats_qa_v1`, без принудительного ON. Четыре сочетания выключателей, настоящий DEMO-баннер и полноэкранный показ,11обычных игр при automatic OFF без SDK-запросов. Обычные интервалы210/180/10/220сохранены. Итог отдельного QAключа:обаOFF. Старые визуальные QA222–224не используются для проверки RC.

`tools/build_android_automatic_ads_probe.ps1 -BottomBanner` создаёт отдельный пакет. `/rc-refresh` лишь перечитывает Firebase, локального `/banner-config` нет. `tools/qa_ad_formats_remote_config.mjs` управляет только отдельным QAключом с резервной копией/ETag/сверкой остальных параметров. Python-проверки используют `ADB_PATH` и необязательный `ANDROID_SERIAL`, не содержат идентификатора устройства владельца. Настоящие игроки/покупки не используются.
