# Физический телефон для проверки Untouch

## Названия и копии — решение Алексея 18.10.2026

На телефоне оставлять актуальную основную версию; две старые QA-копии удалены по прямому поручению. В название каждой новой установки автоматически добавляется `versionCode`: например, `Untouch 179`. Временные изолированные тестовые сборки явно называются `QA179 Untouch`. Номер берётся из Flutter/Gradle, вручную название перед каждой сборкой не менять. Основной пакет `com.best4u.untouch` обновлять только поверх установленного, без удаления/очистки данных. Новую установку проверять по числу пакетов, фактическому названию и сохранению аккаунта/баланса.

Обновлено: 12.10.2026. Источник: прямое сообщение Алексея и USB-проверка.

У Алексея есть **Huawei P30 Lite (MAR-LX1M)**. Он часто может подключать его кабелем к компьютеру. При необходимости использовать физическое устройство для проверки игры; перед работой проверить подключение, а если телефона нет — попросить Алексея подключить его.

Подтверждённая конфигурация 12.10.2026: Android10/API29, экран1080×2312, отладка поUSB разрешена. Подключение и обновление игры проверены: [отчёт](../memory/tasks/2026-10-12-huawei-usb-test.md).

Физический телефон особенно полезен для проверки плавности, задержки управления, звука, Google-входа и поведения после сворачивания. Измерения на эмуляторе не заменяют эти проверки. Для Flutter измерять кадры в profile или release, а не debug: [официальное руководство](https://docs.flutter.dev/perf/ui-performance).

## Рабочий порядок

1. Проверить `adb devices -l`; выбирать физический телефон явно, если эмулятор тоже подключён. Серийный номер не публиковать в документации.
2. Зафиксировать версиюAPK, режим сборки, настройки звука, частоту экрана, заряд/температуру и энергосбережение.
3. Основную игру обновлять без удаления приложения и очистки данных. Для автоматических замеров использовать отдельный пакет `com.best4u.untouch.uiprobe` с тестовыми данными и перехваченными серверными вызовами.
4. Проверять движущуюся сцену, реальное управление, старт/проигрыш и окна отдельно. Сохранять сырые измерения, прогрев и повторные прогоны; не объявлять среднюю частоту кадров доказательством отсутствия рывков.
5. Не выполнять настоящие оплаты и не отправлять сообщения. Выбор Google-аккаунта выполняет владелец.
6. Между активными проверками и после них останавливать тестовую игру: остановки автоматического жеста недостаточно, если враги/музыка продолжают работать. Алексей явно потребовал это12.10.2026. Не оставлять движущуюся сцену на телефоне во время работы над кодом или подготовки отчёта. Основную игру возвращать только для непосредственной приёмки; не начинать раунд без нужды.
7. Доступность телефона проверять при каждой задаче; разрешение использовать устройство не означает, что оно постоянно подключено.

Текущая диагностика: [план и измерения](../memory/tasks/2026-10-12-huawei-performance.md).

12.10.2026 Алексей попросил, чтобы Huawei не блокировался во время USB-проверок. По его указанию оставлено `stay_on_while_plugged_in=2`: экран не гаснет автоматически при USB-питании; без кабеля обычный тайм-аут сохранён. Это не отключение пароля/защиты телефона. Не возвращать эту настройку в0 после теста автоматически; временные изменения восстанавливать к текущей настройке владельца. Игра между проверками всё равно должна быть остановлена.
