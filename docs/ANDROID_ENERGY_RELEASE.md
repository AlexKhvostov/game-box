## Состав серверного архива

`deploy/` соответствует **корню существующего сайта**: 10 PHP-файлов `api/` и одна схема `admin/`. Загружать только этот allowlist после резервной копии. Нельзя переносить корневую папку архива целиком на сайт. `operator/` и `reference/` предназначены для закрытой работы оператора, не для веб-публикации.

Существующие `tg_common.php`, `mobile_google.php`, `mobile_identity.php`, `mobile_beta.php`, `mobile_google_nickname.php`, `mobile_pace.php`, `mobile_play_rtdn.php`, `admin.php`, `config.php`, JWT vendor и приватные конфигурации остаются зависимостями установленного сервера. До замены проверить их наличие и совместимость. Посторонние правки редактора, Telegram API/Stars, лендинг, приватные настройки, ключи, игроки и опубликованный JSON в архив не входят. Пофайловые SHA256 находятся в `manifest-sha256.json`.

`operator/telegram-web/config/gameplay-config.json` содержит **только справочный блок Android** с `enabled:false`. Это вход для merge-инструмента, а не полная конфигурация игры. Никогда не загружать его вместо действующего JSON.

## Порядок выпуска после согласования

1. Проверить, что Android V2 ещё выключен. Снять резервные копии БД Android, существующих заменяемых файлов и актуальной effective config, сохранить её revision. Рабочие параметры отличаются от репозитория: на момент проверки стены безопасны, риск8/пробег999. Полный репозиторный gameplay-config не публиковать.
2. Доставить `deploy/api/mobile_energy.php` и `mobile_energy_feedback.php`, затем остальные файлы allowlist и схему админки. Не включать V2 до совместимости всего набора. Существующие web/Telegram-операции должны пройти smoke-проверку.
3. В закрытом рабочем каталоге сохранить структуру `tools/` рядом с `telegram-web/api/`. Для `operator/tools/maintain_mobile_energy.php` путь `operator/telegram-web/api` должен указывать на **действующую установленную API-папку** с её приватными конфигурациями и зависимостями, например файловой ссылкой на сервере. Секреты в архив и публичную папку не копировать. Запустить через PHP CLI `tools/maintain_mobile_energy.php --apply`; он явно готовит feedback outbox и дополнительные поля invite ledger. HTTP-доступ к CLI закрыт кодом; всё равно не размещать инструменты в webroot. Проверить результат и наличие резервной копии. В обычных запросах изменения схемы не выполняются.
4. В Google Play подготовить товары из `reference/play-catalog-reference.json`, недельный basePlan `weekly`, страны/доступность и тестировщиков. Это справочник, не формат массового импорта Google. Цены в клиенте берутся из Google ProductDetails; показанные в пробнике доллары синтетические. Проверить подписанный AAB в закрытом Play-треке без настоящих расходов. Проверить покупку/повтор/consume/ack, восстановление, замену тарифов, отмену, непрерывное продление, разрыв, hold/grace/refund и RTDN.
5. Настроить приватные Google credentials/RTDN. Запускать существующий `api/mobile_play_maintenance.php` через закрытый CLI scheduler **каждые15 минут**, отслеживать ненулевой код выхода и `pending entitlements`. При неизвестном продлении циклы сохраняются, платный прогресс ограничивается известным expiry, забор/новая подписка ждут проверки. Не трактовать сбой Google как подтверждённое отключение.
6. Проверить почтовый транспорт хостинга для `support@untouch.fun`. После отдельного разрешения подключить приватный scheduler `tools/maintain_mobile_energy.php --deliver`. Код использует PHP mail(), транспорт должен быть настроен на сервере. Отзыв/награда/outbox уже атомарны; задержка письма не повод повторно начислять энергию. В локальных проверках был только подставной почтовый приёмник.
7. Скачать **свежую** effective config. Из `operator/` вызвать `python tools/prepare_android_energy_config.py --input <fresh.json> --output <new-disabled.json>`. Вход не перезаписывается, меняется только `economy.androidEnergyV2`. Проверить diff и актуальную revision в действующей админке. Для разрешённого включения отдельно подготовить новый файл с `--enable`; не обходить проверку revision. Все `game.*`, прочая экономика и Telegram-настройки должны совпасть с исходным снимком.
8. После готовности каталога, схемы, scheduler и новой Android-сборки разрешённо включить V2. Проверить новый тестовый аккаунт20+полная20, перенос существующего `lives+2*crystals` с одной полной20, повторный вход без повторной миграции, забор, стоимость1/2/3, ручные награды, приглашения и подписку. Не использовать реальные аккаунты игроков для разрушающих проверок.

## Удалённые настройки

Бесплатные ёмкость/время/награды меняются в изолированном Android-блоке существующей админки; текущие циклы сохраняют снимок. С15.10.2026 19:22:57 действует отдельная совместимая chargePolicy20/8h для всех батареек, в том числе уже оплаченных, с сохранением прогресса. OriginalSKU20/12h в платёжной истории сохранён, новое обещание8h хранится отдельно. Активная версия политики зафиксирована: следующий общий переход времени потребует истории политик, простой произвольной смены поля для всех оплаченных циклов сейчас нет. Firebase Remote Config отдельно не подключается. Цена меняется в Google Play. Состав платного товара, ёмкость и время платных батареек **не меняются на уже предложенном SKU**: заранее создать новую версию SKU, внести её в приватный `energy_products`, затем выбрать публичной админкой. Такой выбор проверен локально без новой APK; полностью произвольное изменение прежнего оплаченного SKU не поддерживается.

## Откат

До первой миграции и при выключенном флаге возможен возврат резервных копий кода. После миграции нужен совместимый V2 сервер/клиент и сохранение V2 wallet/очередей/ledger. Возврат старого `lives/tokens` как текущих денег или восстановление БД поверх новых оплат недопустимы. `enabled:false` — условие запуска миграции и новых покупок; это **не универсальная остановка всех операций уже мигрировавшего кошелька**. Для аварийного обслуживания использовать согласованный maintenance с сохранением данных, затем исправлять V2. Реальные необратимые действия в этой задаче не выполнялись.
