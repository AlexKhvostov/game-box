# Android: сроки хранения и удаление

Редакция18.10.2026. Рабочая политика для GP06; действует для нового Android Supabase, не для Telegram/MySQL.

| Данные | Срок / критерий |
|---|---|
| Профиль/Auth, прогресс, результаты, отзывы, приглашения, сырые покупки | Пока профиль используется; после подтверждения запроса удалить из рабочей базы в течение30календарных дней. Нельзя восстанавливать удалённый профиль из старой копии |
| Закрытый журнал исполненных действий поддержки |90дней с completed_at; ежедневная cleanup_privacy_logs. Незавершённые обращения не очищать до исполнения |
| Auth audit в PostgreSQL |30дней; та же ежедневная процедура. В проверенном проекте строк0 |
| Внешние журналы Supabase API/БД |Текущий Free:1день по тарифу; не смешивать с auth.audit_log_entries. Экспорт журналов не включён |
| Локальные диагностические выгрузки и ручные копии с данными игроков |Не дольше30дней с создания; DPAPI вне Git, только для восстановления/диагностики. Оператор удаляет истёкшие копии перед/при исполнении запроса; не переносить их в release/evidence/public |
| Обезличенные отметки использованных/удалённых покупок |Только хеш без UID, имени, email, токена и заказа. Пока сервер принимает соответствующий тип квитанции Google Play: это защита от повторной выдачи. При окончательном прекращении приёма таких квитанций удалить отметки в течение30дней |
| Переписка поддержки |До завершения обращения, затем90дней, если нет конкретного законного основания; о специальном удержании сообщить пользователю с составом, причиной и сроком |

Supabase Free не предоставляет нам историю ежедневных резервных копий для восстановления как Pro/Team; не обещать7/14дней. При появлении ручной копии действует наш30дневный предел. Данные у Google/Yandex находятся также под их политиками; удаление игрового профиля не удаляет заказы из Google и не отменяет подписку.

SQL-функция private schema/security invoker, исполнение только служебным postgres cron. Перед запуском на рабочей базе проверить dry-run: просроченных записей сейчас0. Игровые документы/кошельки/сырые квитанции этой процедурой не удаляются. Индекс только на completed_at закрытых обращений. Ежедневный запуск00:20UTC, соответствующий03:20Минск, через существующий pg_cron; без новых сервисов/расходов.

Источники, сверены18.10.2026: [Supabase Free logs](https://supabase.com/pricing), [резервные копии](https://supabase.com/docs/guides/platform/backups), [Auth audit](https://supabase.com/docs/guides/auth/audit-logs). Фактический тариф проверен через Supabase get_organization. Изменение тарифа/поставщика требует обновить опубликованные сроки.


## Публичные имена —18.10.2026
Принятие правил(версия/время) и собственный список скрытых UID хранятся в профиле до изменения/удаления; список также в защищённом кэше устройства. Жалобы private documents/publicReports: отправитель/цель, снимок публичного имени, причина из списка, время/решение. Срок90дней от createdAt независимо от статуса, затем ближайшая ежедневная очистка тем же cron; при удалении отправителя/цели удаляются жалобы и ссылки цели из чужих списков скрытия. Решения moderation в support_actions completed90дней с ежедневной очисткой. Наружу почтой эти записи не пересылаются. Публичные игры/места/балансы при модерации не меняются. Миграция `20261018175715_android_public_name_moderation.sql` применена к рабочей базе18.10.2026; ежедневный cron сохранён, игровые документы не удалялись.
