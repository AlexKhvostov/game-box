# Android Energy V2: контракт реализации

15.10.2026. Рабочая техническая спецификация к принятому плану. Изменения имён согласуются между исполнителями до интеграции.

## Платформа и включение

Необязательный блок `economy.androidEnergyV2`, `enabled` (серверное включение), `revision` (строка версии). V2 клиент отправляет `economyVersion:2` в guest/profile/round_start/wallet; старый сервер не подтверждает V2. При отсутствии серверного включения клиент сохраняет старую работающую экономику; новый UI/модель тестируются изолированно. Запрещён молчаливый локальный перевод подтверждённого сервера без включения.

## Кошелёк

V2 wallet: `energyVersion:2`, `energy:int`, `energyConfig:object`, `batteries:list`, `energySubscription:object|null`, `claimed:list`, `unlocked:list`, остальные исторические поля сохраняются для аудита. Battery: `id:string`, `startedAt:int ms`, `capacity:int`, `durationMs:int`, `initialUnits:int` (0 или capacity), `revision:string`. Начисление `min(capacity, initialUnits + floor(max(0,serverNow-startedAt)*capacity/durationMs))`; расчёт по времени сервера, клиент отображает по смещению `serverNow`. При ручном положительном заборе все активные батарейки начинают пустой цикл на текущих условиях. При нуле сброса нет. Подписочные батарейки независимы от бесплатной. Окончание права обрезает начисление моментом expiry, отключаемые целые единицы один раз переходят на баланс; остальные циклы сохраняются.

Config: `enabled`, `revision`, `initialEnergy:20`, `batteryCapacity:20`, `chargeHours:12`, `baseAttemptCost:1`, `helmetExtraCost:1`, `jumpExtraCost:1`, `rewards:{achievement:10,ad:20,google:10,age:10,feedback:20,invite:20}`, `packages:list`, `subscriptions:list`. Неподтверждённые цены не показываются как реальные цены Google. SKU имеют неизменяемый состав; админка выбирает подготовленные версии.

## Операции

Через существующий wallet operation (owner/idempotency сохраняются): `energy_claim`, `energy_reward` args `{id}` (google/age/achievement ID), `energy_age_completed` args без группы/возраста, `energy_feedback` args `{comment,rating?}`. Ответ — обычный profile с V2 wallet. Готовность Google проверяется сервером; age — только минимальный факт. Клиент ждёт подтверждения, не показывает успешное начисление оптимистично. Повтор возвращает текущее подтверждённое состояние без повторной награды.

`round_start`: persisted requestId, `economyVersion:2`, `helmet:bool`, `jump:bool`, revision. Подтверждённый повтор того же id возвращается до проверки текущей revision. Контекст сохраняет стоимость и усиления. `round_cancel` возвращает стоимость только не начатого раунда по тому же id с ограничением времени, атомарно относительно finish. Практика отдельная, не отправляет результаты/баланс на сервер. Ошибки ресурсов/версий не переходят в бесплатную практику.

## Границы

Старые кошельки/очереди поддерживаются явно; ни Telegram энергия, ни общая физика не меняются. Не удалять ledger. Нет реальных платежей или писем в тестах. Реальная активация внешних товаров/рекламы/доставки — отдельная проверяемая зависимость.

## Уточнения, закреплённые реализацией и независимой проверкой

- `round_activate` подтверждает начало до первого игрового кадра. После подтверждения возврат через `round_cancel` запрещён. Если за время ответа поле ушло в фон/под другое окно, тот же активированный receipt ожидает следующего видимого касания без нового списания. Повтор ещё не активированного start доступен и при нулевом остатке энергии.
- `claimed`: Google/возраст/отзыв используют `energy_google`, `energy_age`, `energy_feedback`; существующие achievement ID сохраняются. `energyGoogleReady` и `energyAgeCompleted` не содержат возрастной группы.
- Известная дата окончания последнего ACTIVE/GRACE периода ещё не доказывает прекращение автопродления. До сверки Google `energySubscription.awaitingReconciliation:true`, `pendingSince`, `endConfirmed:false`; платный прогресс ограничен `expiresAt` / battery `activeUntil`. Циклы сохраняются; весь забор и новая оплата блокируются `subscription_verification_pending`, показано «Проверяем подписку»/«Восстановить». Бесплатный прогресс продолжается. Непрерывное подтверждённое продление продлевает прежние циклы; подтверждённое окончание сохраняет остаток один раз. Нужен серверный reconciliation каждые 15 минут с контролем сбоев.
- Пакеты: неизменяемые `energy_100_v1`, `energy_250_v1`, `energy_500_v1`, `energy_1000_v1`. Тарифы: `energy_batteries_2_v1`, `energy_batteries_5_v1`, basePlan `weekly`. Подготовленные версии `_vN` выбираются удалённо; приватный registry фиксирует состав, в том числе платную ёмкость/время. Public offer сообщает `capacity`, `chargeHours`, `batteryCount`, `additionalBatteries`, `periodDays`. `play_quote` сохраняет предложение/владельца до оплаты, но кредитование не доверяет клиентскому quoteID.
- Кэш денег — одна запись `energy_v2_snapshot` с `owner`, `wallet`, `serverNow`; владелец проверяется по защищённым данным аккаунта. После запуска без сети часы снимка заморожены до подтверждения сервера. В работающей сессии время зарядки идёт по монотонным часам, независимо от перевода часов телефона.
- Все записи очереди/архива проверяют результат сохранения. Неподтверждённые legacy операции архивируются с исходными ID/владельцем/аргументами/причиной, а не теряются и не превращаются в новые начисления. Подтверждённые server receipts переигрываются без дублей. Отказ проверки подписки архивируется и освобождает очередь, чтобы не блокировать последующий `play_sync`.
