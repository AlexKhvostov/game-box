# Продуктовая аналитика Android / AppMetrica

24.10.2026. SDK `appmetrica_plugin: 4.1.0`, схема событий **2**.

Рабочая карточка **untouch_Android / 6377692**, техническая **Untouch Android QA analytics / 6377701**. QA не является статистикой реальных игроков.

## Согласие и возраст в Android ·25.10.2026

Текущий код больше не активирует AppMetrica до выбора возраста и явного разрешения. Порядок первого запуска: родной Google chooser (отмена сохраняет гостя) → существующее окно возраста → вопрос аналитики только при явном18+. Для младше18/неизвестного возраста сбор выключен, вопрос не появляется. Google-вход и рекламное согласие сами по себе аналитику не разрешают.

`AnalyticsConsent` хранит выбор на устройстве в `analytics_consent_granted_v1`, первый показ в `analytics_consent_prompt_seen_v1`. «Разрешить» сохраняет согласие и сразу закрывает окно; «Без аналитики», крестик, системный Back закрывают без согласия и без следующего окна состояния. Подробности возвращаются к вызвавшему окну. Одна кнопка в существующем аккаунте открывает единое состояние с переключателем и меняющейся иллюстрацией. Исправление возраста на<18 немедленно выключает сбор, удаляет разрешение и блокирует повторное включение; возврат на18+ не восстанавливает прежнее согласие.

Активация SDK после согласия сначала использует `dataSendingEnabled:false`, ручные сессии, отключённые location/adIDs/crashes/ANR/revenue; отправка включается отдельным вызовом после повторной проверки согласия. Отзыв сразу отсоединяет обработчик игровых событий и вызывает native sending=false; останавливает lifecycle/timer, удаляет локальную очередь сводок. Очереди защищены от отложенного отзыва/повторного включения. Время окон и незавершённый игровой раунд не переносятся через границу согласия. Уже переданные Яндексу данные автоматически не удаляются.

Пользовательский текст/реальные компоненты: `lib/features/profile/analytics_consent_sheet.dart`; утверждённый русский оригинал — единственная текущая галерея UI Kit. Схема событий2, период30с и разделение QA/production не менялись. Флаг сборки `APPMETRICA_ENABLED=false` по-прежнему имеет приоритет и полностью запрещает активацию даже при сохранённом согласии.

Для новой физической проверки: `tools/build_android_analytics_consent_probe.ps1` и `tools/test_android_analytics_consent_phone.py`. Это отдельный пакет `.uiprobe.consent`, реальные виджеты/нативный QA-SDK; Google и игрок представлены локальными fixtures без живого входа/сервера. Старый `appmetrica_probe.dart` теперь явно задаёт согласие взрослого QA-fixture и проверяет события, а не опрос пользователя.

Состояние выпуска и ограничения: [отчёт Android-согласия](../memory/tasks/2026-10-25-android-analytics-consent-runtime.md). Исторические записи ниже о запуске до возраста относятся к прежнему коду. Публичную policy и DataSafety нужно сверить с новым поведением в общей подготовке выпуска; локальный перенос не является публикацией приложения или policy.

## Отправки

| Событие | Что входит | Частота |
| --- | --- | --- |
| game_start | run_id, helmet, jump, контекст на старте | Оставлено по последнему решению Алексея; один фактический старт |
| game_finish | Завершённая попытка, время/риск/путь, экипировка и использования, все счётчики тормоза | Один обычный финиш collision; прерванные/убитые попытки специально не восстанавливаются |
| ui_summary | Счётчики экранов, именованных окон, времени окон, показов/кликов, страниц, настроек, выбора способностей и доступности наград | Раз в300с foreground с первого собранного действия (проверка раз в5с), при уходе в inactive/фон, смене контекста/профиля; пустые пакеты не отправляются |
| Редкие бизнес-исходы | game_start_blocked, energy_empty, reward_claim_started/result, ad_started/result, purchase_started/result, account_action_result, invite_action, share_action, feedback_result | Сохраняются отдельными; не ждать следующей игры |

`ability_available` / `ability_used` больше не отправляются. `screen_view`, `window_opened/closed`, `page_selected`, `feature_shown/clicked`, `setting_changed`, `ability_configured`, `reward_available` — внутренние сигналы для ui_summary, не отдельные SDK-события. screen=playing вообще не добавляет UI-счётчик, поскольку игра уже учтена game_start. Старые tap/open/plus/share действия собираются как legacy_<event>_count; редкие старые начисления остаются совместимостью.

Общий контекст: analytics_schema_version=2, analytics_environment, config_revision при наличии. run_id и конфигурация game_finish берутся со старта, чтобы изменение настройки не переписало историю попытки. Первые установки/версии/устройства/сессии даёт SDK. Почта/имя/тексты/токены/коды приглашений не передаются; профиль — локальный псевдоним либо хеш ID аккаунта, это не полная анонимность.

## Тормоз в game_finish

- brake_enabled, brake_ready_count, brake_use_count, brake_wait_count.
- brake_wait_sum_ms, brake_wait_min_ms/max_ms, brake_first_wait_ms (последние3 только при измерениях).
- brake_first_wait_bucket: no_use / under_1s / 1_3s / 3_5s / 5_10s / 10s_or_more.
- brake_wait_under_1s_count, brake_wait_1_3s_count, brake_wait_3_5s_count, brake_wait_5_10s_count, brake_wait_10s_or_more_count.
- brake_ready_unused_at_finish, при true — brake_ready_unused_ms.
- brake_usage_state: disabled / never_ready / ready_unused / used. used может одновременно иметь неиспользованную готовность на финише.
- jump_equipped/helmet_equipped, jump_use_count/helmet_use_count; автоматическое срабатывание шлема не нажатие кнопки.

Только активные часы симуляции. Ожидание захватывается до нажатия, до сброса readyAt. Интервалы определяются до округления; отдельные измерения округляются до целой миллисекунды. Незавершённое ожидание не входит ни в сумму завершённых, ни в интервальные счётчики. Среднее всех использований: SUM(brake_wait_sum_ms)/SUM(brake_wait_count)/1000; нулевой знаменатель означает отсутствие результата, а не нулевое время. Не усреднять средние партий без весов. По пяти интервалам нельзя получить точную медиану. Ожидание не доказывает поиск кнопки.

## ui_summary

Плоские ключи из инструментированных кодов, не из пользовательского текста:

- window_<window>_open_count/close_count/active_ms, <window>_opened=true.
- screen_home_view_count, screen_result_view_count.
- feature_<placement>_<feature>_shown_enabled_count/shown_disabled_count/click_count.
- page_<container>_<page>_select_count.
- setting_<setting>_change_count/last_value.
- ability_<ability>_configure_count/last_selected.
- reward_<placement>_<reward_type>_available_count.
- legacy_<event>_count.

Общие поля: summary_id, interval_started_at_ms, interval_ended_at_ms (Unix ms устройства), foreground_ms, flush_reason. Названия частей ключей ограничены ASCII-буквами/цифрами/_/- до64символов, иначе other. Максимум180разных ключей за пакет; при превышении counters_truncated=true. Число повторов одного действия не увеличивает число ключей. Нет неограниченного массива всех нажатий и нет press_1/press_2.

Окно учитывает только foreground и отсутствие перекрывающей модалки. На границе пакета время разделяется без повторного открытия; поэтому во втором пакете может быть время/закрытие без открытия. Показ функции: минимум50%видимости, текущий маршрут, один показ на состояние экземпляра без повторов от перерисовки. Не все кнопки инструментированы. Разные placement могут описывать один жест; сумма всех click_count не равна физическим нажатиям.

До приёма нативным SDK UI-пакеты хранятся локально (до16пакетов); повтор при старте/возврате/следующейсводке. Переполнение удаляет старейший и помечает ui_outbox_overflow=true. После приёма SDK сетевые повторы выполняет SDK. Смерть процесса между приёмом SDK и записью локального подтверждения может дать повтор summary_id: в выгрузке удалять повторы. Накопленные только в памяти действия до ближайшей сводки могут потеряться при убийстве процесса. Абсолютную доставку/однократность не обещаем.

## Как анализировать

[Рабочая панель](https://appmetrica.yandex.com/dashboard?dashboardId=8f6276bc-d091-4841-8b1e-d7d261bb6c5d&appId=6377692), [отчёт событий](https://appmetrica.yandex.com/statistic?appId=6377692&reportId=88394c70-6a04-441b-9a47-4ddeb55143e1).

Всегда выбирать analytics_schema_version=2. В кабинете смотреть duration_bucket, brake_usage_state, brake_first_wait_bucket, экипировку. Это распределение ПО ПОПЫТКАМ. В ui_summary флаг profile_opened — отрезки/пользователи с открытием, не число открытий. Отсутствие ключа в конкретном пакете — отсутствие этого действия, если пакет не усечён; старые версии и неподдерживаемые функции не приравнивать к нулю.

Обычная таблица событий не суммирует числовые значения параметров автоматически. Для сумм использований/открытий, взвешенного среднего и распределения ПО ИСПОЛЬЗОВАНИЯМ нужна выгрузка Reports/Logs API и расчёт по числовым значениям. ## Сборка и ключи

С24.10.2026 по решению Алексея обычный `tools/build_phone_apk.ps1` использует **тестовую AppMetrica6377701 / environment=qa**. Основной ключ **6377692 / environment=production** выбирается только с `-AppBundle` (AAB для Google Play) либо `-PlayStore` (сопутствующий APK для Google Play). `-ProductionRelease` запрещает отладочные игровые возможности, но сам по себе НЕ выбирает основную аналитику. Ключ фиксируется при сборке, загрузка файла в магазин ничего не переключает.

Общий `tools/appmetrica_build_config.ps1` читает выбранный ключ из локального DPAPI вне Git и проверяет соответствие назначения. Явная подстановка основного ключа в QA либо QA-ключа в Play останавливает сборку. Отсутствующий/невалидный ключ тоже останавливает её; только явный `-DisableAnalytics` разрешает сборку без аналитики. `tools/build_android_appmetrica.ps1` использует то же правило: APK по умолчанию QA; `-PlayStore` или `-Artifact appbundle` — production, с `-Probe` эти варианты запрещены. TestTools/preview/debug/demo запрещены в Play-сборках.

В аргументах процесса передаётся путь временного файла определений, ключ не печатается; файл удаляется после сборки. QA-аналитика не означает тестовый игровой кошелёк: обычный APK сохраняет основной код/сервер, меняется только получатель событий. Служебный `-Probe` отдельно включает искусственный кошелёк. `tools/test_appmetrica_build_config.ps1` проверяет маршрутизацию без сборки и без вывода ключей.

Для физического QA: `tools/build_android_appmetrica.ps1 -Probe -KeyPath <локальный DPAPI QA> -Mode profile`, затем `tools/appmetrica_qa_server.py` и `tools/test_appmetrica_phone.py`. Это отдельный пакет com.best4u.untouch.uiprobe.analytics, фактический нативный SDK, тестовый кошелёк без живого аккаунта/оплат. Для проверки настоящего300-секундного отрезка с открытым профилем — tools/test_appmetrica_summary_interval_phone.py; это дополнительная проверка длительностью около6минут, игра в ней не запускается. Основную игру не очищать и не удалять. После теста остановить QA.

Отсутствующий ключ, веб-платформа и выключенная аналитика оставляют безопасный пустой обработчик; ошибки телеметрии не прерывают игру. Автоматические геолокация, рекламные идентификаторы, отчёты об авариях/ANR и Revenue отключены. Обычные события покупок не являются финансовым реестром.
