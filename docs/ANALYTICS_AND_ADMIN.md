# Аналитика, сбор данных и веб-админка

Документ для менеджера: **что сделать**, **что нужно от вас**, **где это взять**.  
Код приложения пока не обязателен — сначала доступы и решения, потом разработка.

См. также: [ADS_AND_BILLING.md](ADS_AND_BILLING.md) · [GOOGLE_PLAY_PUBLISH.md](GOOGLE_PLAY_PUBLISH.md) · [FIREBASE_SETUP.md](FIREBASE_SETUP.md) · [GAMEPLAY_ADMIN.md](GAMEPLAY_ADMIN.md)

---

## 1. Зачем это нужно

Вы хотите видеть:

- кто играет (анонимные пользователи / установки);
- сколько раз заходили и сыграли;
- что нажимают в приложении и **как часто** (счётчики).

В Game Box уже есть Firebase Auth (анонимный вход) и Firestore (рейтинг `scores`).  
**Счётчиков кликов и сессий пока нет** — их нужно начать писать из приложения.

---

## 2. Два слоя (рекомендация)

| Слой | Что даёт | Кому подходит |
|------|----------|----------------|
| **A. Своя админка** (Firestore + веб-страница) | Список игроков, счётчики по каждому uid | Вам как владельцу продукта — «сколько раз нажали Daily / Boost / Gift» |
| **B. Amplitude** (или Firebase Analytics) | Воронки, удержание, дашборды без своей разработки UI | Продуктовая аналитика «как люди играют по дням» |

**Практика для Game Box:**  
1) сначала **слой A** (ваши счётчики + простая админка);  
2) параллельно или чуть позже — **Amplitude** (удобные графики).  
Можно слать одно и то же событие в оба места.

Firebase Analytics (бесплатно в консоли Google) — запасной вариант вместо Amplitude, если не хотите отдельный сервис.

| Что нужно от вас | Зачем | Где взять |
|------------------|-------|-----------|
| Подтвердить, что можно писать коллекцию `players` в Firestore | Хранение счётчиков | Firestore → Create database (если ещё не создана) — [гайд](https://firebase.google.com/docs/firestore/quickstart) |

**От вас на старте достаточно:** открыть Firebase Console и сказать разработчику «админку делаем на этом проекте». Пароль админки можно задать вместе при первом деплое.

### Для Amplitude (слой B) — если подключаем

| Что нужно от вас | Зачем | Где взять |
|------------------|-------|-----------|
| Аккаунт Amplitude | Дашборды и события | [amplitude.com](https://amplitude.com/) → Sign up (есть бесплатный тариф для старта) |
| **API Key** проекта | Вшить в приложение | Amplitude → Project Settings → API Key |
| Решение: EU или US дата-центр | Где хранятся данные (GDPR) | При создании организации Amplitude спросит регион |

### Для Firebase Analytics (альтернатива Amplitude)

| Что | Где |
|-----|-----|

Имена событий в приложении:

| Событие | Когда |
|---------|--------|
| `app_open` | Старт приложения (после Firebase) |

Проверка: DebugView в GA / Firebase Analytics → Events (задержка до суток в обычных отчётах).

## 4. Слой A — своя админка: как сделать (по шагам)

### Шаг 1. Модель данных в Firestore

Коллекция: `players/{uid}`  
`uid` = анонимный Firebase Auth id игрока (уже появляется при старте приложения).

Пример полей:

```text
createdAt          — первый запуск
lastSeenAt         — последний заход
sessionsCount      — сколько раз открывали приложение
gamesStarted       — стартов партий
gamesFinished      — завершённых партий
bestTimeMs         — лучшее время (опционально)
platform           — android / ios
counters: {
  tap_lives, tap_crystals, tap_record,
  open_daily, open_shop, open_earn, open_lives,
  claim_daily, claim_gift, buy_life_pack, tap_plus, …
}
```

Полный лог каждого клика с временем **не нужен** в MVP — только числа «сколько раз».

### Шаг 2. События в приложении (разработка)

Разработчик добавляет маленький модуль счётчиков:

- при старте приложения → `sessionsCount++`, `lastSeenAt`;
- старт / конец партии → `gamesStarted` / `gamesFinished`;
- открытие шитов и важные кнопки → инкремент ключа.

**Важно:** писать в Firestore **пачками** (раз в 30–60 сек или при уходе в фон), а не на каждый тап — иначе вырастет счёт за Firestore.

### Шаг 3. Правила безопасности Firestore

Игрок может писать **только** `players/{свой_uid}`.  
Чтение всех игроков — только для админки (пароль / Cloud Function / ваш Google-аккаунт).

Кто настраивает: разработчик + вы проверяете в Firebase → Firestore → Rules.

### Шаг 4. Веб-страница админки

Минимум:

- вход (пароль или ваш Google);
- таблица: короткий uid, lastSeen, sessions, games;
- клик по игроку → все счётчики;
- сверху KPI: всего игроков, сумма игр (по возможности).

Деплой: Firebase Hosting → ссылка вида `https://ВАШ-ПРОЕКТ.web.app`.

### Шаг 5. Приёмка (вы проверяете)

1. Поставить свежий APK, поиграть, понажимать Daily / Gift / Boost.  
2. Открыть админку → появился ваш uid, счётчики выросли.  
3. В Firestore Console → `players` → документ с полями.

## 5. Слой B — Amplitude: как подключить

### Шаг 1. Регистрация (вы)

1. Зайти на [amplitude.com](https://amplitude.com/), создать организацию.  
2. Создать проект, например `Game Box Android`.  
3. Скопировать **API Key**.  
4. Передать ключ разработчику **не в публичный чат с репозиторием**, а в личку / менеджер паролей.

### Шаг 2. В приложении (разработка)

- Flutter SDK Amplitude (официальный пакет).  
- При старте: `setUserId(firebaseUid)`.  
- Те же события, что и для админки: `session_start`, `game_start`, `game_finish`, `ui_tap` с параметром `button=…`.

### Шаг 3. Проверка (вы)

Amplitude → User Look-up / Events → после запуска APK события появляются через несколько минут.

### Шаг 4. Дашборды (вы или аналитик)

Готовые чарты: DAU, retention D1/D7, воронка «открыл кристаллы → Daily → claim».

## 7. Сравнение вариантов (чтобы не путаться)

| Вопрос | Своя админка | Amplitude | Firebase Analytics |
|--------|--------------|-----------|---------------------|
| Список игроков с кастомными счётчиками | Да | Частично (User Look-up) | Слабо |
| Воронки и retention из коробки | Нет (сами) | Да | Да, проще |
| Стоимость старта | Firestore + Hosting | Бесплатный тариф → платный рост | Бесплатно |
| Контроль данных | Полный (ваш Firebase) | У Amplitude | У Google |
| Сложность разработки | Средняя | Низкая–средняя | Низкая |

**Рекомендация продукта:** админка + Amplitude. Если бюджет/время жмут — админка + Firebase Analytics.

## 8. Порядок работ (для планирования)

1. Вы: доступы Firebase; решение «Amplitude да/нет».  
2. Разработка: счётчики в приложении → Firestore.  
3. Разработка: простая веб-админка.  
4. Вы: проверка на телефоне.  
5. (Опционально) Amplitude API Key → события в SDK.  
6. Privacy Policy обновить перед релизом в Play (см. документ про Google Play).

---

## 9. Риски (коротко)

- Анонимный uid = установка, не ФИО человека.  
- Без батчинга — лишние деньги Firestore.  
- Админку нельзя оставлять открытой без пароля.  
- Ключ Amplitude не коммитить в публичный репозиторий.

3. Смотреть события: Firebase → Analytics → Events (или DebugView для мгновенной проверки).  
4. Позже по желанию: своя админка (слой A) и/или Amplitude.
