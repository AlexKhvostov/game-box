# Проверка Untouch на виртуальном Android

06.10.2026: установлен официальный Android Emulator 37.2.12 и создан `Untouch_API_36` (Pixel 7, Android 16/API 36, Google APIs, x86_64). Аппаратное ускорение AEHD 2.2 доступно. Unity для этого Flutter-проекта не требуется.

Образ Google `x86_64-36_r07.zip` проверен по SHA-1 из официального каталога: `c6bf44bdcd885bb902b4ba752d111a073ad7a817`. После зависания загрузки SDK Manager архив скачан напрямую с `dl.google.com` и распакован в Android SDK; AVD создан штатным avdmanager.

Установлена существующая APK `releases/android-v1.0.29_20261006_021643_351/Untouch-1.0.29+30.apk`. Установка: Success. Android подтвердил package `com.boxgame.game_box`, versionName 1.0.29, versionCode 30, minSdk 24, targetSdk 36. Холодный запуск MainActivity: Status ok. Игровой экран и профиль просмотрены; журнал crash пуст после двух запусков.

Начало попытки не подтверждено: первый жест показал `Could not start a run. Check your connection.`, секундомер остался на нуле. После перезапуска профиль отображается, повторный жест также не подтвердил игровой цикл. Интернет эмулятора и DNS игрового домена доступны; HTTPS GET мобильного API с компьютера вернул 200, schemaReady=true, mobile-api-v1.0.4. Это не доказывает успешность авторизованного запроса round_start из APK; причина отказа требует отдельной диагностики.

Снимки находятся в `docs/release-evidence/android-emulator-1.0.29-*.png`. Эмулятор оставлен открытым с приложением для ручной проверки.

## Повторный запуск

В Android Studio откройте Device Manager и нажмите запуск у `Untouch_API_36`. Также предусмотрен `tools/start_android_emulator.ps1`. Для управления на виртуальном телефоне используйте мышь: нажатие и перетаскивание имитируют один палец.

Это проверка эмулятора, а не физического телефона. Полный игровой цикл, настоящий мультитач, производительность реального устройства, реклама и покупки не приняты. APK не пересобиралась и не публиковалась.

## Исправление начала попытки — 06.10.2026

Причина установлена на настоящем HTTPS-хостинге: `Authorization` доступен через `getallheaders()`, а `$_SERVER['HTTP_AUTHORIZATION']` и `REDIRECT_HTTP_AUTHORIZATION` пусты. Регистрация гостя не требовала Bearer, поэтому профиль создавался; авторизованный старт отклонялся. API теперь читает заголовок из обычной/redirect-переменной сервера и, при их отсутствии, из заголовков запроса без учёта регистра имени. Проверка секрета остаётся обязательной.

Проверки: 43 прежних MySQL-сценария и новые HTTPS-сценарии профиля, отсутствующего/неверного Bearer, старта и повторного requestId прошли. Повторный старт списывает жизнь однократно. Все таблицы, тестовый endpoint и временная копия JWT удалены.

API `mobile-api-v1.0.5_20261006_093345_748` опубликован стандартными сборщиком и deploy-скриптом. Резервная копия `predeploy-20261006_093440_883397`, 3 изменённых/17 неизменных файлов сверены SHA-256; HTTPS подтвердил новую версию. Секреты и опубликованный JSON не заменялись.

На той же APK 1.0.29+30 в эмуляторе подтверждены старт, перемещение свайпом, секундомер, списание одной жизни (30 → 29), столкновение и экран результата 1.183 секунды/22 шага. После проигрыша SDK показал объявление с маркировкой DEMO AD; оно закрыто штатным крестиком, рекламные переходы и оплаты не выполнялись. Crash-журнал пуст. Снимки `android-emulator-1.0.29-auth-fixed-start.png` и `android-emulator-1.0.29-auth-fixed-score.png` просмотрены. Первичная проблема старта устранена; это не полная приёмка AP7.2 на физическом Android.
