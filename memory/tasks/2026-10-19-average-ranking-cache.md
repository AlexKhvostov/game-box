# Серверный кэш среднего рейтинга

Обновлено: 2026-10-20 00:02 Europe/Minsk. Этап: готово, внедрено и проверено.

Поручение Алексея: аккуратно внедрить хранение готового среднего, уточнить место хранения. Квадратичная формула пока только UIKit; текущую формулу игры сохраняем.

| Блок | Статус | Критерий |
|---|---|---|
| Обследование | Готово | Телефон уже сохраняет готовый ответ в SharedPreferences по аккаунту; сервер пересчитывает SQL при каждом чтении |
| Серверный кэш | Готово | Закрытая таблица, повторное чтение без вычисления 50 результатов; инвалидирование при изменении попыток и правил; свежие имена/места |
| Проверки | Готово | 116 backend PASS; локальная сверка старого/нового ответа и плана SQL PASS: повторный запрос не выполняет чтение scores и не обновляет кэш. Изменения/удаления/давность/RC/изоляция/доступ проверены |
| Внедрение | Готово | Миграция 20261019205914 применена, android-api v20 ACTIVE. 21 прежняя зависимость сохранена побайтно; заменён wrapper среднего и добавлен кэш. Реальная база: 29 профилей, 29 строк кэша; прежний и новый ответы равны, документы неизменны, повторный запрос не читает scores |
| Итог | Готово | Отчёт и доказательства сохранены; локальный коммит своих файлов, без push/публикации Android |

Кэш — производные данные в приватной схеме untouch; история попыток остаётся источником истины. Пересчёт после изменения выполняется при следующем чтении; игровые раунды не получают дополнительный расчёт среднего. Ключ правил включает версию алгоритма, окно, порог и вес. Места/видимость/имена вычисляются по актуальным профилям при выдаче. Кэш не доверяет числу с телефона.

До внедрения получен deployed android-api v19; его average-ranking.mjs совпал с исходной локальной копией. Полная резервная копия в .private/average-ranking-cache-20261019/android-api-before.json. При публикации берём прежний серверный пакет и меняем только average-ranking.mjs, добавляем average-ranking-cache.mjs; чужие локальные изменения в сервер не попадут. Для отката достаточно прежнего пакета, новые таблицы можно оставить: они не меняют оригинальные данные. Отсутствие таблицы/гонка удаления профиля имеют fallback на прежний расчёт.

Сценарий принятой попытки дополнительно проверен на изолированной PostgreSQL-совместимой тестовой базе: round_start → activate → finish → allPeriods обновил среднее один раз; повтор finish сохранил баланс и не инвалидировал кэш повторно. 10 целевых PASS после общего прогона 116 PASS. Реальные раунды/аккаунты для этого не создавались.

Кэш в untouch.average_rank_cache. Версии исходных попыток в untouch.average_score_revisions, обновляются триггером в той же транзакции. Профиль удаляется → кэш агрегата удаляется каскадно. Таблицы в приватной схеме, RLS включён; anon/authenticated не имеют прямого доступа. Метаданные ревизий не сбрасываются при удалении профиля, чтобы старый запрос не мог повторно использовать прежнюю версию. Квадратичная формула не внедрялась.

Доказательства: docs/release-evidence/average-ranking-cache-20261019/. Следующий шаг — обычная игра и наблюдение; обновление приложения для серверного кэша не требуется.

[Итог и доказательства](../../docs/release-evidence/average-ranking-cache-20261019/README.md). Телефонная проверка аутентифицированного HTTP-рейтинга не выполнялась; рабочая БД и изолированный движок проверены. Для обычного использования отдельный следующий шаг не нужен.
