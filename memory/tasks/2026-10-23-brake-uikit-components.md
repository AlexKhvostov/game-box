## Цель и критерии готовности

Добавить в существующий живой UI Kit (`docs/design/simple-energy-bonus-20261016/live-kit/`) повторно используемые компоненты кнопки и шкалы. Это HTML/CSS/SVG галерея проекта, не Figma и не основной игровой код.

- Выбранная белая улитка на салатовой кнопке, строго сверху, размер кнопки не больше героя. Никаких надписей внутри кнопки.
- Незаряженная кнопка заметно сильнее обесцвечена. Четыре состояния: не заряжена, заряжается, готова, эффект нажатия.
- От 12 часов по часовой стрелке заполняются и кольцо, и САМ ФОН кнопки; символ улитки остаётся видимым.
- Шкала скорости под полем: внутренний диапазон 0–150, видимых чисел/единиц нет, только «скорость врагов» мелко внутри. Заполнение теперь светло-красное; сбрасываемый правый хвост зелёный, затем исчезает. Это новое требование заменяет прежние бирюзовый рост/красный хвост.
- Живая демонстрация нажатия/перезарядки/роста и торможения, отдельные закреплённые состояния, рабочий локальный просмотр и проверки на узкой ширине.

## Границы

Поручение относится к компонентам UI Kit. Не внедрять механику в Android/Telegram runtime, не менять RC, серверы, APK и релизы. Новые файлы/минимальные подключения в существующую галерею, чужие изменения сохранить. Git push не выполнять.

## Рабочие решения агента

Чистый SVG/CSS для кнопки и шкалы, чтобы состояние фона вычислялось точно, а анимацию можно было проверить. Изображение выбранного эскиза — референс, а не целый растровый интерфейс. Использовать текущие ассеты героя/шапки из UI Kit, реальные данные не нужны.

## Результат

- [Живой компонент](http://127.0.0.1:8896/#brake), локальный сервер только 127.0.0.1 (Python PID25120, запущен для просмотра).
- [Контракт API и проверки](../../docs/design/simple-energy-bonus-20261016/live-kit/BRAKE-KIT.md).
- [Четыре состояния](../../docs/design/simple-energy-bonus-20261016/live-kit/evidence/brake-20261023/button-states.png), [нажатие в сцене](../../docs/design/simple-energy-bonus-20261016/live-kit/evidence/brake-20261023/live-press.png), [зелёный хвост](../../docs/design/simple-energy-bonus-20261016/live-kit/evidence/brake-20261023/speed-green-tail.png), [браузерные проверки](../../docs/design/simple-energy-bonus-20261016/live-kit/evidence/brake-20261023/browser-checks.json).

Реализованы управляемые mountBrakeButton/mountSpeedBar, destroy и отмена анимаций. Площадка не больше героя, кнопка остаётся круглой. Почти серый незаряженный фон и приглушённая улитка, салатовый фон постепенно заполняется от12часов по часовой стрелке вместе с кольцом. Нажатие локальное, враги кратко подсвечиваются и плавно замедляются. Прогресс скорости светло-красный; хвост зелёный и полностью исчезает. Никаких чисел на шкале.

Визуально осмотрены desktop, состояния, нажатие, хвост и мобильный390px. Проблема узкого меню галереи исправлена только при body[data-kit-view=brake], остальные вкладки сохраняют прежние стили. Подтверждены ширины320/360/390/430 без переполнения и с читаемым горизонтальным меню. Полный реальный8-секундный цикл в браузере PASS, промежуточная готовность/повторное нажатие/пауза/выход и новая вкладка/reduced-motion PASS, ошибок/404/внешних запросов нет. Целевые расчётные проверки, предыдущая модель Моих попыток и33demo-rules PASS. node --check/ограниченный git diff --check PASS.

Ограничения: это живой браузерный UI Kit с демонстрационной моделью. Телефон и реальные коллизии героя с педалью не проверялись; в галерее ручное нажатие. Основной игровой код/Android/Telegram runtime/RC/данные/сервер/релизы не менялись; Git push/публикаций не было.
