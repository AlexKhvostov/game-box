# Восстановление rewarded-рекламы после ревью

Обновлено: 18.10.2026 Europe/Minsk. Источник: прямое поручение Алексея «Доведи ее до рабочего состояния…исправлять не отключать».

Цель: кнопка вызывает настоящий Yandex SDK, объявление показывается, после onRewarded и закрытия сервер ровно один раз начисляет награду; раннее закрытие и ошибки не начисляют. Сохранить аккаунт и остальные исправления ревью.

| Этап | Статус | Критерий / результат |
|---|---|---|
| Диагностика / checkpoint | В работе | Исходная точка 9c7bfae, tracked tree чист; телефон подключён. Отключение в AdsService/engine подтверждено |
| Серверная сессия и штатный callback | Запланировано | Одноразовая привязанная к игроку сессия, идемпотентность, cooldown, старый прямой watch_ad отклоняется |
| UI и регрессии | Запланировано | Кнопка запускает SDK; нет ложной награды, повторов или потери очереди при сетевой ошибке |
| Настоящий SDK на Huawei | Запланировано | Загрузка → показ → earned → закрытие, тестовый пакет с SDK; основной аккаунт без очистки |
| Доставка сервера / APK | Запланировано | Сервер обновлён, новая подписанная версия поверх175; подтверждённый рекламный кредит |
| Итог / память | Запланировано | Факты проверок и ограничения записаны, игры остановлены |

Yandex официально не поддерживает server-side rewards: https://ads.yandex.com/helpcenter/en/support/faq/sdk-integration . Не имитировать SSV и не менять рекламную сеть. Рабочий выбор: штатный SDK callback + серверная одноразовая сессия и ограничения повторов. Клиентский callback сам по себе не защищает от модифицированного клиента. Внутренняя сборка сохраняет официальные demo IDs (не live-монетизация). Правила возраста/отзыва сохраняются.

Используемые навыки: session-memory, supabase. Git push / Play / live реклама не входят в работу.
